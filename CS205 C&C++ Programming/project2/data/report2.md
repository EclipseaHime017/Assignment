Then,  we define a function to multiply two matrices. Here, we using pointers pointing at the matrices themselves to simulate ```reference``` which is not equipped in C language. 

```c
void mult(const Matrix *ptrA, const Matrix *ptrB, Matrix *ptrC)
{
    clock_t start,end;
    double time;
    if ((*ptrA).col != (*ptrB).row || ptrA == NULL || ptrB == NULL || ptrC == NULL)
        printf("Matrices are invalid! Be careful about that A column equals B row.");
    else{ 
        start = clock();
        for(int i = 0; i < (*ptrB).col; i++)//varying B column
        {
            for(int j = 0; j < (*ptrA).row; j++)//varying A row
            {
                for (int k = 0; k < (*ptrA).col; k++)//varying A column and B row
                {
                    (*ptrC).pdata[i+j*(*ptrC).col] = 0;
                    //C[j][i]
                    (*ptrC).pdata[i+j*(*ptrB).col] += (*ptrA).pdata[(*ptrA).col*j+k] * (*ptrB).pdata[(*ptrB).col*k+i];
                }
            }
        }
        end = clock();
        time = ((double) (end - start)) / CLOCKS_PER_SEC;
        printf("It costs %lf second.\n",time);
    }
}
```

### Java version

The code structure of java version is similar to that of c version in how we process them.

To have a better comparison with C version, we tried to make them as the same as possible so that their difference will mostly be how they calculate matrices and how fast they are originally supposed to be.

```java
import java.util.Random;

class Matrix {
    int row;
    int col;
    float[] pdata;
}

public class Main {
    public static void main(String[] args) {
        int row1, row2, col1, col2;
        java.util.Scanner scanner = new java.util.Scanner(System.in);
        System.out.println("Please input a number as the row of your first matrix");
        row1 = scanner.nextInt();
        System.out.println("Please input a number as the column of your first matrix");
        col1 = scanner.nextInt();
        System.out.println("Please input a number as the row of your second matrix");
        row2 = scanner.nextInt();
        System.out.println("Please input a number as the column of your second matrix");
        col2 = scanner.nextInt();

        int[] size = {row1, row2, col1, col2, row1, col2};

        if (col1 != row2 || row1 <= 0 || row2 <= 0 || col1 <= 0 || col2 <= 0) {
            System.out.println("Invalid matrix. Please check your columns and rows.");
            return;
        } else {
            Matrix[] matrix = new Matrix[3];
            Matrix matrix1 = new Matrix();
            Matrix matrix2 = new Matrix();
            Matrix matrix3 = new Matrix();
            matrix[0] = matrix1;
            matrix[1] = matrix2;
            matrix[2] = matrix3;

            for (int i = 0; i < 3; i++) {
                matrix[i].row = size[2 * i];
                matrix[i].col = size[2 * i + 1];
                matrix[i].pdata = new float[matrix[i].row * matrix[i].col];
                if (matrix[i].pdata == null)
                    System.out.println("Wrong allocation; Fault Gate 1.");
            }

            geneM(matrix1);
            geneM(matrix2);
            mult(matrix1, matrix2, matrix3);
        }
    }

    static void geneM(Matrix ptr) {
        Random rand = new Random();
        for (int i = 0; i < ptr.row; i++) {
            for (int j = 0; j < ptr.col; j++) {
                float rand_float = rand.nextFloat();
                ptr.pdata[j + i * ptr.col] = rand_float;
            }
        }
    }

    static void mult(Matrix A, Matrix B, Matrix C) {
        long start, end;
        double time;
        if (A.col != B.row)
            System.out.println("Matrices are invalid! Be careful about that A column equals B row.");
        else {

            start = System.nanoTime();
            for (int i = 0; i < B.col; i++) {
                for (int j = 0; j < A.row; j++) {
                    for (int k = 0; k < A.col; k++) {
                        C.pdata[i + j * C.col] = 0;
                        C.pdata[i + j * B.col] += A.pdata[A.col * j + k] * B.pdata[B.col * k + i];
                    }
                }
            }
            end = System.nanoTime();
            time = (double) (end - start) / 1000000000.0;
            System.out.println("It costs " + time + " second.");
        }
    }
}
```

### $2. Factors influencing time cost

>Square demonstrates speed between different language, and it is not complete because matrices are not all squares.
Therefore, we now implement matrices of the same data size to observe their difference in multiplication. 

Here, we surprisedly found that even if matrices are of the same data size(meaning that they have same number of numbers in each matrix), it is evident that the first matrix of more row number ran much slower than those of less row number.

This is because fundamentally, when matrix A(mxn) multiply with matrix B(nxm), there will undergo operations for a total number of ```(2n-1)*m^2``` times. When ```m*n``` is a constant number, then it becomes  ```(2Const-m)xm```, which implies only m influence time of calculation. Consequently, if m -> too large, the multiplying time costs increase.

Besides, we made three assumptions as additional possible reasons for such a phenomenon.

1. The speed was highly influenced by loops.
   
2. The speed was highly influenced by writing.
   
3. The speed was highly influenced by reading.

@3 To prove that the third assumption is correct, we first elaborate why third assumption. 

I made a guess that programs working resembles people using automatic rifles. That is, we load bullets(data) first and then we shoot(run program). Since it is inefficient to load one bullet and shoot every time, we may using something like clips to load a lot of bullets in one go. I believe it might be the same for computer to load many data in a cache to accelerate the program.

Thus, in my source code of generating numbers of matrices, they are arranged linearly in memory and follows an order of row-priority(left to right, up to down). Thus, when I use them, computer preferentially load row data(left to right), it will be fast to undergo calculation in this order. Nevertheless, if calculation is accomplished from up to down, it might probably be slower. 

To prove it does matter, we change the way that we used to arrange matrices numbers from row priority to column priority, and again compile and link with other files.
